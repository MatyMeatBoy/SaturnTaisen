# HD mod: handoff to finish it from another PC

Written 2026-11-18, after v0.2.2-alpha. For whoever continues the HD work on a different machine. It says what is done, what is missing for 100 %, what travels through Git and what does not, and the order that makes sense. Counts are the ones in [HD progress](../HD_PROGRESS.md), which is generated by `tools/build_hd_progress.py` from `config/hd-progress.json`.

## What a release needs from HD work

Nothing manual. The player's PC builds the pack from their own files with `tools/taisen_setup.py`:

- Portraits: `config/hd-portrait-recipe.json`, regenerated by `python tools/build_hd_recipe.py` from `config/hd-portrait-reviewed.json` plus the owner's matcher project. `tests/test_taisen_setup.py` fails if an approved portrait is missing from the recipe or if the count disagrees with `docs/HD_PROGRESS.md`.
- Backgrounds: the 19 identities in `assets/generated/pc-backgrounds/provenance.json`.

A new HD category needs the same three things: tracked data that names the pairs (identifiers and hashes only, never pixels), a step in `prepare_hd` that builds it from the player's files, and a runtime consumer. Until the third exists, do not count it as integrated.

## Order of work

1. **T67 — decode the Saturn `BG*.BIN` and `NC*.BIN` formats** by tracing the SH-2 loader (`docs/research/pc-asset-census.md` records what was already ruled out). This is the key: with decoded native images, scene pairs can be found by comparing files instead of screenshots, and it also unblocks NC bodies. Needs only the discs and the SH-2 disassembler in the SDK (`local/deps/satrecomp/tools/sh2dis.py`); no runtime build.
2. **T74 — runtime consumer for scene images.** Identify the native background on screen (hash of the native plane, as the KABE path does with its palette fingerprint, or the decoded `BG*.BIN` once T67 lands) and draw the PC image in the scene rectangle, keeping the approved Zoom framing and the fallback to native. This is an SDK patch (0054 or later) and a runtime build, so it has to be qualified like any runtime: hash comparison against the current executable on the existing replays, zero interpreted blocks. Do T83 (broken accents in the runtime's feature texts) and T57 (cursor auto-hide, patch0052) in the same build so the runtime is qualified once.
3. **T76–T79, T710, T711 — BG matching by shard** while 1 and 2 are in progress; one shard per PR. Method in [bg-matching-shards.md](bg-matching-shards.md) and [bg-matching-progress.md](bg-matching-progress.md): decode the PC images once with `tools/decode_spred.py`, capture with `sakura.exe --headless --unthrottled --shot-every 125:PREFIX` from several states in parallel, rank with `tools/match_bg_screenshots.py` (pass the shard prefixes), confirm every candidate by eye, then add the pair to `config/hd-scene-bg-pairs.json` and the log. A margin under 0.05 is ambiguous; lighting variants share structure (BG1119 day / BG1120 night).
4. **Then the remaining 501 scene files** (EVENT, CG, ENDING, TITLE, ICATCH) with the same method, and their step in `prepare_hd`.
5. **T52 — the last two portraits.** `00a1`: compare both strips in game after swapping them offline (T45), keep the base and the Saturn mask. `0169`: the PC art differs; decide with the owner whether a different design is acceptable before accepting it.
6. **T53 — videos.** The 50 clips are paired; what is missing is playback of the PC MPEG-1/MP2 files in the runtime and a check of audio, subtitles and skipping.
7. **T54 / T23 / T19 — HUD, menus, tactical, NC bodies.** Bodies keep one height-based scale and the head/torso axis; never stretch to fill a box.

## Rules that are easy to break

- A pair is accepted only with identity and evidence. Ambiguous matches are rejected; a good thumbnail is not evidence. Check VDP2 blends before blaming a missing animation.
- PC art keeps uniform proportion. Do not move the approved Zoom framing. Original mode must stay pixel-identical.
- Never commit pixels, extracted PC files, discs, states or anything under `local/`. Pair data is identifiers, offsets and hashes.
- "Matched", "prepared", "integrated" and "verified in game" are four different columns. Update `config/hd-progress.json`, run `python tools/build_hd_progress.py`, and keep the README block in step; a screenshot or a passing suite does not certify a chapter.
- The shipped runtime is the test.4 executable (674,182 blocks, SHA-256 `df68e9db…`, patch0050). Any runtime change needs a new qualified build; do not ship a runtime because it compiles.
- Automated runs must not disturb the owner: run `sakura.exe` directly with `SATRECOMP_WINDOW_HIDDEN=1` and absolute `--disc`, `--settings`, `--backup`; test the launcher with `--screenshot` and an absolute `SATURN_TAISEN_FIRST_HOME`.

```powershell
git clone https://github.com/MatyMeatBoy/SaturnTaisen.git
```


Read this block first; the sections above describe the state of 2026-11-18.

**Done and merged**

- T74: the runtime draws the PC picture of a recognised scene under the native overlays, found by the palette fingerprint of the picture layer (patches 0059-0061; table generated by `tools/gen_scene_bg_table.py`, 459 pictures). BG3xxx/BG4xxx are character cut-outs on a key colour and are never drawn as pictures.
- Patch 0057 (portrait white fade at every weight), 0058 (stable Zoom box, choice hold, text tracking), 0060/0061.
- The 674,182-block AOT base was recovered from the shipped executable (`tools/extract_blocks_from_exe.py`); a runtime with patches 0001-0061 builds in about 25 minutes on 16 threads and keeps the v0.2.2 guest hashes (3 scenarios, 1,200 frames each, 0 interpreted).

**What is left, in the order that makes sense**
1. T96/T67 formats: `TITLE*` (76,736 and 115,248 bytes) and `NC*.BIN` (structure notes in `saturn-bg-format.md`). Method that worked: look at the data per hypothesis, compare against the PC picture, do not trace the loader first.
2. Runtime consumer for the 16 IC eyecatches and for `BBG`/`EVE` pictures (palette fingerprint, like T74); the eyecatches are the episode cards, so the 16:9 framing decision of T87 comes first.
3. Bodies (NC): dump the VDP1 commands of a dialogue with a body on screen and match the texture bytes against `NC*.BIN`, then a recogniser like the portrait pack.
4. Videos (T53): PC MPEG-1/MP2 playback is not in the runtime (needs a decoder dependency: a decision).
5. HUD/menus (T54/T23) and the tactical mode (T12).
6. Performance (T86): slow frames are emulation frames (SH-2 about 6.5 ms, VDP software about 7.2 ms, sound about 2.4 ms); presentation is 3-5 ms.
7. Needs the owner: the Spanish LOADING scroll and the episode title cards as generative art (no image tool was available), and publishing a release with the new runtime.

**Rules learned the hard way**
- A pair is a pair only by identity and evidence; a correlation score is not an eye check (patch0059 once drew 84 character cut-outs because the score was high).
- Running Python from a heredoc under this harness collapses `\x00`-style escapes: write such literals with the editor or build them with `chr(92)`.
- `build_runtime.py` fails with "local edits outside the recorded patch stack" when the shared SDK differs from the composed tree, also if `GIT_CONFIG_*` forces `core.autocrlf=false` on a CRLF checkout; run it with the user's normal git config.
